## 1. W1：可降级条件

对应 PRD 13.3。不改告警规则、不改 9 秒超时、不改演示场景 A/B 的温度表。

### 1.1 提示词

在 `prepareBayAIInput` 的系统提示中写明：只有五条全部满足时才可以 `downgrade`，否则用 `maintain` 或 `escalate`。

1. 告警级别是警告，不是危险。
2. 程序给出的热点区域不是车底。
3. 图上的热点集中成一小块，不是大片扩散。
4. 当前最高温不高于 10 秒前，也不高于 30 秒前。
5. 10 秒前或 30 秒前的最高温缺失时，不能判断趋势，不得降级。

充电状态继续作为必须写入说明的情况。充电中的车轮热点，在五条都满足时可以降级。

### 1.2 程序检查

`validateBayAIOutput` 在现有检查之外，增加对降级建议的条件核对。建议不是降级时，不做这四项检查。

核对用的是已经送给模型的同一份证据：告警级别、热点区域、当前最高温、10 秒前最高温、30 秒前最高温。

| 条件 | 不通过时 |
|---|---|
| 告警级别不是 `warning` | 拒绝 |
| 热点区域是车底（`underbody`） | 拒绝 |
| `peak10SecondsAgoC` 或 `peak30SecondsAgoC` 为 `null` | 拒绝 |
| 任一历史最高温低于当前最高温 | 拒绝 |

拒绝时抛出新的错误码 `AI_OUTPUT_DOWNGRADE_RULE`，整次结果仍是「AI 说明不可用」。程序不把 `downgrade` 改写成 `maintain`。条件 3（热点是否集中）不由程序判断。现有的危险、电池异常、无法判断不得降级的检查保留。

### 1.3 评估预期

重新跑 `scripts/live-bay-ai-check.mjs` 的正式组。10 月 10 日的报告保留，不覆盖。预期改为：

| 帧 | 预期建议 |
|---|---|
| 场景 A 第 0 秒 | 维持 |
| 场景 A 第 30、60 秒 | 降级 |
| 场景 B 第 28、42 秒 | 升级 |

两个反例帧只供这次评估使用，不进入演示播放器，界面若展示须标明测试专用：

| 反例 | 预期 |
|---|---|
| 车轮区热点，温度快速上升 | 不降级 |
| 车底热点，温度缓慢下降 | 不降级 |

不放宽校验，不延长 9 秒超时。模型不听从条件时，结果如实记入报告。运行前须得到用户同意，因为会消耗 API 用量。

### 1.4 测试

在 `tests/bay-ai.test.mjs` 增加断言：缺历史、车底、温度上升、危险级别时，降级输出被 `AI_OUTPUT_DOWNGRADE_RULE` 拒绝；四条都满足时，降级输出仍可通过。不在单元测试里调用真实模型。

## 2. W2：超时排查

对应 [PHASE2_PLAN.md](PHASE2_PLAN.md) 的 P5。不放宽 9 秒超时，不加入预热、自动重试或录屏备用。

在 `scripts/live-bay-ai-check.mjs` 增加单独入口（例如 `--timing`），不改第 1.3 节的预期通过率统计：

- 使用同一次进程、同一条服务商连接。
- 先连续调用场景 A 第 0 秒帧 10 次，再连续调用场景 B 第 28 秒帧 10 次。两次调用之间不等待，方便看出第一次是否明显更慢。
- 每次记录三段毫秒数：准备图片与请求正文、等待服务商响应、收到正文后的解析与校验。某一段失败时，已测到的段保留，未发生的段为空。
- 报告写入 `.sites-runtime/live-bay-ai/`，与「成因和建议是否符合预期」的评估报告分开。10 次样本只能提示冷启动或某一帧偏慢，不能当成稳定的延迟结论。

运行前须得到用户同意，因为这 20 次调用会计入 API 用量。单元测试只检查分段计时的记录方式，使用测试替身，不调用真实模型。

## 4. 提示音与久未处理

对应 PRD 13.6。不改变告警级别，不发送短信、电话或即时消息。实现放在第 3 节的布局改动之后、开发者走查之前，走查才能听到声音。工时从缓冲出；时间不够时不能用它替换必须保住的演示文稿、AI 重新评估和代码仓库。

### 4.1 声音

用 Web Audio 振荡器合成，不增加音频文件。数值是原型参数。

| | 警告 | 危险 |
|---|---|---|
| 频率 | 880 Hz | 1320 Hz |
| 每声时长 | 120 毫秒 | 80 毫秒 |
| 声与声的间隔 | 80 毫秒 | 50 毫秒 |
| 一声组里的声数 | 2 | 3 |

同一时刻有多条待处理告警时，只播放最高级别的那一组，不叠播。页面尚未获得发声许可时，显示「点击启用提醒音」，点击后才能出声。

### 4.2 重复、静音与闪烁

- 未处理时间由服务端按告警进入待处理的时刻计算，浏览器刷新不重置。警告满 60 秒、危险满 30 秒后视为久未处理。
- 久未处理之前每 10 秒播放一次；之后每 5 秒播放一次，声音种类不变。车位格子和队列条目闪烁，并显示「已 N 秒未处理」。文字和图标仍然保留，不只靠闪烁或颜色。
- 选定级别后停止该告警的声音和闪烁。再次回到待处理时，计时和声音从头开始。
- 单个告警静音 60 秒和全局静音只存在浏览器里，不写入决定记录。刷新或静音到期后恢复出声。全局静音开关始终显示当前是否静音。
- AI 不可用或关闭时，提示音照常。

### 4.3 测试

纯函数测试覆盖：未到阈值每 10 秒、超过阈值每 5 秒、多条告警只取最高级别、选定级别后不再播放、静音窗口内不播放。浏览器检查覆盖启用提示、闪烁和「已 N 秒未处理」文字。不断言扬声器真正出声。
