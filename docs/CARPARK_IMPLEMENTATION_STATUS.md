## 第 2 轮：服务端播放器与车位状态

- `backend/sim/player.mjs`：启动即产生 11 个车位的仿真首帧，每秒推进；B2-11 永不发帧。时钟与定时器可注入，重复推进同一秒不重复发帧；采样时间遵循逻辑时钟，避免定时器抖动制造危险速率。
- `backend/bays.mjs`：复用共享规则引擎，严格校验 24 × 32 帧，每个车位只在内存保留最近 60 帧；首帧温度未达阈值时显示正在接入；超过 5 秒无新帧才断线；创建／升级规则告警，断线或降温不解除待处理告警。
- `backend/carpark.mjs`：仿真会话、独立 SQLite `demo_sessions` / `bay_alerts` 表、重置与场景启动。所有仿真接口带来源与不可导出标识；不写入原 `telemetry` / `events` / `audit` 表。
- `backend/server.mjs`：新增车位读取与演示控制 API，沿用本机来源与 CSRF 检查；WS `bays` 只发送 12 个车位的摘要，`alert` 发送新建／升级事件，完整矩阵仅通过车位详情 API 获取。
- NASA 工作台仅响应 `telemetry` / `events` 消息，避免每秒的车位摘要触发实测记录刷新；浏览器回归新增此检查。

### 已接入的接口

| 方法／路径 | 内容 |
|---|---|
| `GET /api/carpark` | 布局、会话、12 个车位摘要 |
| `GET /api/bays/B2-02` | 最新完整帧、规则结果、热点区域、60 帧最高温序列、当前告警 |
| `GET /api/alerts` | 当前规则告警，危险优先，再按创建时间排序 |
| `POST /api/demo/scenario` | `{ "name": "A", "ai": false }` 或场景 B；先清空当前会话，再从场景第 0 秒播放 |
| `POST /api/demo/reset` | JSON 空对象 `{}`；删除当前演示会话及告警，开始新会话 |

写接口需 `Content-Type: application/json` 与 `/api/health` 返回的 `X-Voltguard-Csrf`。输入无效返回 422，来源／CSRF 不符返回 403，未知车位返回 404。`POST /api/frames` 仍未实现。

WS 沿用 `{ type, report }` 包装：`bays.report` 为 `{ session, bays, sourceType, exportable }`，`alert.report` 为 `{ event, alert }`。每批仅一次摘要；帧处理与推送在同一事件循环内完成。

场景或重置后，11 个有帧车位的正常首帧仍短暂显示「正在接入」，下一秒收到可比较帧才显示正常；这是缺少速率证据时的设计行为。A 的超温首帧直接警告，B2-11 始终无数据。

## 第 5 轮：保安决定、记录与告警生命周期

### 查看效果

打开 **http://127.0.0.1:4173/?view=carpark**，填写值班员代号（例如 P1），启动场景 A 后选择 B2-08，选择「降级 · 观察」并点击「记录决定」。告警进入「处理中」段并标注「已降级 · 观察中」，车位仍为警告，以琥珀色虚线标示。

- 降级／维持／升级可重复选择；附加动作可以单独记录。每次提交追加一行，底部展开记录可看服务端操作时的完整帧、序号、时间、查看时长及当时级别。历史记录不随新帧改变。
- 场景 B 的 B2-02 约第 28 秒警告、第 42 秒危险。维持警告后规则升危险会回到待处理；危险告警禁用降级，服务端也会拒绝迟到的降级请求。
- 选择「拨打 999」同时按升级记录，并显示手动 `tel:999` 链接。所有附加动作仅记录选择，不自动派人、通知或拨号。升级为危险后显示按现场应变计划安排处置的提示。
- 值班员名称自报，界面和记录均注明身份未验证；保存在浏览器 `localStorage`，存储不可用时仍能操作。名称不是登录或身份认证。查看时长从打开当前车位详情计起，离开车位页或重置会话后重新计时，不限制提交速度。
- 本轮 AI 区显示「AI 说明不可用」，操作固定 `aiStance: none`、`aiRunId: null`，记录 `aiUnavailable: true`。

### 服务端与持久化

- `backend/bay-decisions.mjs`：验证级别、附加动作、1–20 字代号、非负整数查看时长与 AI 不可用路径；危险不得降级。选择 `call_999` 的有效级别为 `escalate`。
- `POST /api/alerts/:id/decisions` 接收 `{ level, extras, aiStance, aiRunId, operator, viewedMs }`，只记录附加动作时 `level: null`。沿用本机来源／CSRF；成功 201，决定冲突和字段校验 409（明确错误码）；非法 JSON／内容类型仍按公共解析器返回 422。帧由服务端取最新值，拒绝浏览器提交 `frame`。
- `backend/bays.mjs`：待处理／处理中／已降级／已结束生命周期，危险只升不降。已降级告警在最高温比降级时高出 ≥3°C、格点速率 ≥1°C/s 或规则升危险时回到待处理；维持警告遇规则危险同样回到待处理；已处理危险不再重回待处理。
- 已处理告警必须取得连续 10 秒 `normal` 才结束。接收或采样间隔超过 5 秒、坏点／资料不足及非正常规则会重新开始计时；单独记录附加动作不会重启有效的恢复区间。待处理告警温度恢复也不自动结束。原 A/B 仿真最终仍超温，演示中使用重置清空；自然结束用注入帧测试验证。
- `bay_decisions` 独立表只追加，保留完整帧与级别变化；决定与告警更新同一事务，写入失败不会改变内存或数据库告警。`GET /api/bays/:id` 返回当前演示该车位全部决定；结束后记录仍保留，重置当前会话级联清除告警与决定。仿真标记／不可导出标记随记录返回，不写入实测 `telemetry` / `events` / `audit`。
- WS 新增 `decision` 元数据通知，不带矩阵；选中车位在同一帧序号下也能刷新决定和告警变化。前端请求中的重试可合并到当前读取之后，防止漏掉同帧操作结果。
- 队列先待处理、后处理中，每段危险优先再按创建时间排序；处理中段包含观察状态。离线禁用操作，失败提交保留选项，语言切换保持表单。Service Worker 更新为 v15。
