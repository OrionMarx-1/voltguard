# 第二阶段实现记录

## 可降级条件

- 提示词明确五项条件；充电状态仍须说明，热点集中程度由模型看图判断。
- 校验绑定发送时的证据。违规降级返回 `AI_OUTPUT_DOWNGRADE_RULE` 和不可用结果，不改写建议。电池异常和无法判断的原有禁令保留。
- 场景 A 首帧预期维持，中段与末段预期降级；场景 B 预期升级。提供独立的 `buildBayDowngradeCounterexamples()`，只生成测试专用上升轮区／降温车底帧，不加入播放器。
- 单元测试新增条件边界、提示词、不可变发送证据与反例；AI 浏览器 QA 使用测试替身，首帧确认维持，同时仍验证修改建议会记录为拒绝。
- 本轮不运行真实模型评估。旧报告保留；程序测试与替身 QA 不能证明模型准确率或延迟。

## 六个充电位

- 仅保留单行 B2-01 至 B2-06，全部安装充电器；B2-06 固定没有帧。
- A 移到 B2-03：平时空位，场景开始刚驶入、尚未充电。B 仍在 B2-02。温度表与规则阈值未改。
- 集合、占用、逐秒帧数与方向键的精确测试预期改为新布局；浏览器检查额外核对单行六格、无数据编号及 A 的未充电状态。

## 提示音与久未处理

- 警告两声 880 Hz（120 ms，间隔 80 ms）；危险三声 1320 Hz（80 ms，间隔 50 ms）。用户点击启用后以 Web Audio 合成，不增加媒体文件，多条告警只播放最高可提醒级别。
- 待处理起点独立存储，服务端计算秒数；追加动作及浏览器刷新不重置。选定级别后停止，重新待处理时重置。已有本地表只增加时间字段，没有新增清理或保存期限机制。
- 警告满 60 秒、危险满 30 秒后，原声组由每 10 秒改为每 5 秒，同时车位和队列闪烁，显示未处理秒数；减少动画偏好使用静态醒目标记。告警级别保持不变。
- 单条静音 60 秒和全局静音仅在浏览器内；刷新清除静音状态，但仍显示点击启用声音提示。AI 关闭或不可用时照常提醒。
- 新增 `tests/reminders.test.mjs` 和 `scripts/qa-carpark-reminders.mjs`，检查参数、节奏、优先级、处理、静音、服务端计时和浏览器呈现；不声称验证扬声器实际出声。

## 分段计时入口（仅替身）

- `runBayTimingFixture()` 只接受测试替身，同一个替身依次处理 A 首帧十次，再处理 B 警告帧十次；不加入等待、预热、重试或格式回退。
- 分别记录图片及请求正文准备、等待完整正文、正文解析及输出校验。失败段保留测到的时长，后续未执行段为 `null`；整个流程共用不超过九秒的预算。
- `scripts/check-bay-ai-timing-fixture.mjs` 为独立替身入口，不读取 `.env`、不构造真实服务商。计时报告类型及文件名独立，写入忽略的 `.sites-runtime/live-bay-ai/`；不纳入成因／建议预期通过率。
- 新增 `tests/bay-ai-timing.test.mjs`，检查顺序、精确分段、失败、超时、校验、报告隔离与敏感内容保护。本轮只执行测试，未运行 `live-bay-ai-check`，未发真实 API 请求；无冷启动或服务商延迟结论。

## 本轮验证

- 四项按顺序独立提交，各项提交前全量测试分别通过 101、101、110、118 项；没有跳过、删除或放宽已有断言。
- `qa-carpark`、`qa-carpark-decisions`、`qa-carpark-ai`、`qa-navigation` 和 `qa-carpark-reminders` 最终均输出 `ok: true`。浏览器截图只存放在忽略的 `.sites-runtime/`。
- 计时独立入口由单元测试在禁用 `fetch` 和 `loadEnvFile` 的保护下执行，实际生成的是替身报告。没有执行真实模型评估或真实超时诊断。
- 第一阶段技术设计、演示文稿、发布、商业与订阅、数据清理和本地模型均未改动。
