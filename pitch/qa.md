# 評委問答（20 題）

截至 2026-10-03。答案目标是約 30 秒內說清楚，实际答題時間仍待排練。實作依据见 API.md、README.md、測試及簡報講者備註。

1. **解决甚麼痛點？** 讓量測、缺失資料及判定更容易理解，方便不同角色交接。電車火災是動機，但我們沒有證明所有事故都有可提前觀測的訊號。
2. **真的能預防起火嗎？** 未有這個證據。当前是觀測與交接原型，沒有已驗證的火災預測模型、靈敏度或提前預警分鐘數。
3. **為何用 GenAI？** 雙語解讀和來源整理可能減輕交接負擔；這個效益仍須真人和真實模型測試。數值判定不依赖 GenAI。
4. **為何不用傳統 ML 預測？** 缺少代表性事故／非事故標註與車型資料。目前選擇透明規則；不能拿老化數據冒充火災訓練集。
5. **資料都是真的嗎？** 内建四個 NASA 實验電芯，共 636 个放電循環。它们不是四輛車，也不是四次火災。界面不生成新讀數。
6. **3D 是否是真實電池包？** 是示意模型。NASA 的單通道只畫一個實測标記，未知位置與未測外殼保留灰色。真實整包圖需要多測點和座標。
7. **60／80°C 如何得來？** 是当前原型规则选擇，未經車型校準，也不是消防處规定。须与 OEM／電池專家覆核，不能當作通用安全界限。
8. **容量維護是否代表危險？** 不代表。首循環容量比下降是獨立維護資訊；末次记录三個容量 review、零热规则跨越，不能说三起火警。
9. **AI 已真正接通嗎？** 接入代码和测试完成，尚无 API 密鑰，沒有真實供應商聯調。公开版本也没有云端 AI 服务。
10. **多模態看的是甚麼圖？** 伺服器由已验证測點矩陣生成索引 PNG，和数值一起发给模型。不是從图片反推新的温度或空间布局。单测点图像的额外诊断信息很有限。
11. **RAG 是甚麼程度？** 两个核對過的 FSD 官方頁面，使用小型關鍵字檢索。不是向量資料庫，不是即時搜尋整個網路；未收录的问题返回無匹配。
12. **怎样处理 hallucination？** 重新验证輸入、嚴格 schema、來源白名單、限制字段与部分高风险語句 guard。它们不能證明語義正確，模型結果仍须人員覆核。
13. **斷網或 AI 失败怎樣？** 不产生假答案；保留量測和确定性判定。离线历史資料不能当作实时状態。WebGL 失效可用 2D。
14. **會自動切斷車輛或充電嗎？** 不会。没有制動、充电停机、通风、灭火或电池拆卸控制。实际处理依批准现场预案、OEM 和专业人员。
15. **支援汽车运行中嗎？** 数据契约包含 driving、parked、charging。但没有已连接 OEM 或 CAN／OBD 适配器。授权读数和时钟同步是实际接入的前提。
16. **如何保护个人资料？** 字段白名单、local aliases 哈希、云端最少量測與明確同意，密鑰只在伺服器。哈希不等於匿名，store:false 不等於零保留，正式 PDPO 评估仍待做。
17. **谁付钱，已有客户吗？** 車队／場地營運者是目标客户；B2B 订阅是待驗證假设。沒有合約、已验证价格、營收或 500 个部署。
18. **怎么证明好用和有影响？** 先找至少两名实际角色完成观察任务，记录完成率、交接耗时、错误和反馈。没有已完成用户研究或降低事故率的证据。
19. **WorkBuddy 特别奖准备好了吗？** 已制作portable skill，未安装或使用 WorkBuddy，尚无真实协作截图。不能把 Codex 操作标成 WorkBuddy。奖项规则也需主办方确认。
20. **比赛前还缺甚麼？** 真實 API 联调、专业阈值／安全词句覆核、授权车辆数据、真人试用和五次实际排练，另需团队分工与提交日期确认。
